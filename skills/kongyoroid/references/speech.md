## 読みが決まる順番

`reading` / `plan` はこの順で読みを決める。どこ由来かは `phrases[].accentSource` に出る。

1. **正規化** — 日付 (`2026/09/07` → ニセンニジューロクネン クガツ ナノカ)、時刻 (`9:05` → クジ ゴフン)、バージョン (`v1.2.3` → ブイイチテンニテンサン)、単位 (`3ms` → サンミリビョー、`100kg`、`25℃`)、通貨 (`¥1,200` → センニヒャクエン)、符号と範囲 (`-5`、`10〜20`)、`#42` → ナンバーヨンジューニ、URL とメールアドレス (記号ごと読み下す)、Markdown の行頭・強調記号、全角/半角。
2. **英単語のレキシコン** — 695 語の技術系語彙 (`npm` → エヌピーエム、`API` → エーピーアイ、`GitHub` → ギットハブ、`Claude Code`、`deploy` → デプロイ …)。頭字語は「最後の文字の先頭にアクセント」(エーピーア'イ)。`accentSource: "lexicon"`。
3. **形態素解析とアクセント** — jpreprocess (OpenJTalk の Rust 実装) + NAIST-JDic が読み・アクセント核・アクセント句境界を決める。数詞と助数詞 (`一本` → イッ'ポン、`第4章` → ダ'イ/ヨン'ショー)、助詞の付属、母音の無声化 (デ_ス) を含む。`accentSource: "frontend"`。
4. **辞書** — リクエストの `dictionary`、`--dict-entry`、`--dictionary` ファイルの順に表記を読みへ差し替える。`accent` を書けばアクセントも上書き。`accentSource: "dictionary"`。
5. **かな記法** — `kana` を渡すと 1〜4 を飛ばしてその通りに読む。`frontend` が `notation` になる。`'` を書いた句は `accentSource: "user"`、書かなかった句は `"rule"`。

### この段階で必ず疑うもの

フロントエンドは**警告なしで**別の読みを返したり、読めない文字を落としたりする。

| 入力 | 出た読み | 問題 |
| --- | --- | --- |
| `二文目。` | `ニア'ヤメ。` | 完全な誤読 |
| `テストが3件失敗` | `…/サン'ゲン/…` | 助数詞。サンケン ではない |
| `完了しました🎉` | `カンリョー/シマ'_シタ。` | 絵文字が消える |
| `简体` | `タイ。` | 簡体字専用の字が消える |
| `user@example.com` | `ユーエスイーアール、アットマ'ーク、…` | 1 文字ずつ。警告も出ない |
| `kongyoroidsynth` | `ケーオーエヌジーワイ…` | 未知の英単語。`ASCII_WORD_UNKNOWN` の助言は出る |

数詞・助数詞・固有名詞・製品名・略語・記号は**毎回** `reading` の `kana` で確認する。

## 数字と助数詞

数値は**値ごとに読みが変わる**ので、値ごとに確認する。系統的なくせが 2 つある。

### 複合数詞はアクセント句が割れる

1〜10 と 20/30/…/100 のような単独の数詞は 1 句にまとまる。それ以外の複合数詞は、数と助数詞が別のアクセント句に分かれる。1〜30 では 18 個が該当し、**助数詞の種類には依存しない** (件・個・回・人・分・円・% ・ファイル・行・秒 のいずれでも同じ 18 個)。

| 入力 | 読み |
| --- | --- |
| `1件` `10件` `100件` | `イッ'ケン` `ジュッ'ケン` `ヒャッ'ケン` — 1 句 |
| `12件` | `ジュー/ニ'ケン` — 「10」と「2件」に割れる |
| `23件` | `ニ'ジュー/サン'ゲン` |
| `12` (数字だけ) | `ジュー/ニ'` |

`/` はポーズではなくピッチのリセットなので、間は空かないが数がひと続きに聞こえなくなる。数値が原稿の主眼なら `kana` で 1 句にまとめる。

### `件` は 3 で終わる数で連濁する

`3件` `13件` `23件` … は `サン'ゲン` になる。家屋の助数詞 `3軒` と同じ読みで、助数詞を取り違えている。他の助数詞では起きない (`3個` → `サンコ`、`3回` → `サン'カイ`、`3分` → `サン'プン`、`3行` → `サン'ギョー`)。

### 値が実行時に変わるなら読みも生成する

ビルド件数やテスト失敗数のように値が毎回変わる原稿では、`kana` に固定の読みを書くと次の値で壊れる。**テンプレートの穴ごとに `reading` を通し、必要なら値から読みを組み立てる**。`reading` は音声を書かないので安く、合成パイプラインに常設できる。

## 読みを直す 3 つの手段

| 手段 | 使いどころ | 効き方 |
| --- | --- | --- |
| `dictionary` (リクエスト) / `--dict-entry` | 語単位。文脈で読みが揺れる固有名詞・製品名 | その語だけ差し替え、周りの解析は活きる |
| `--dictionary FILE` | 同じ語が何度も出るプロジェクト | 全リクエストに効く。`digest` がキャッシュキーに入る |
| `kana` | 文全体の発音を確定させたい。詩・歌詞・定型アナウンス | テキスト解析を丸ごと飛ばす |

原則は**語単位で辞書、文単位でかな**。文全体を `kana` にすると以後の原稿修正が読みに反映されなくなるので、範囲を広げすぎない。

```sh
# 語だけ直す
kongyoroid speak --text "二文目を読みます。" --dict-entry 二文目=ニブンメ:2 -o a.wav
#   -> ニブ'ンメヲ/ヨミマ'_ス。 (accentSource: dictionary)

# 文全体を確定させる
kongyoroid speak --text "橋の端で箸を使う" --kana "ハシ'ノ/ハシデ/ハ'シヲ/ツカウ。" -o b.wav
```

`--dict-entry SURFACE=READING[:ACCENT]` は繰り返せる。`:ACCENT` を省くとアクセントはフロントエンドに任せる。

## 辞書の副作用

辞書は読みを差し替えるだけでなく、**アクセント句の切れ方も変える**。

| 入力と辞書 | 読み |
| --- | --- |
| `テストは4件失敗しました。` (辞書なし、もともと正しく読める値) | `テ'_ストワ/ヨン'ケン/シッパイ/シマ'_シタ。` |
| `テストは3件失敗しました。` (辞書なし) | `テ'_ストワ/サン'ゲン/シッパイ/シマ'_シタ。` |
| 同上 + `3件 → サンケン` | `テ'_ストワ/サン'ケンシッパイ/シマ'_シタ。` ← 句が融合した |

さらに、**隣り合う語を両方登録すると語が二重に読まれることがある**。`3件 → サンケン` と `失敗 → シッパイ` を同時に登録すると `サン'ケン/シッパイシッパイ` になる。片方だけなら起きない。

だから辞書を足したら、狙った語だけでなく `kana` 全体を読み直す。`dictionaryHits[].applied` が `true` でも、周りの句構造が壊れていないことの保証にはならない。句が融合したり語が重複したりするなら、辞書をやめてその文だけ `kana` で書くほうが安全。

## かな記法

`kana` (`--kana`) に渡す表記。ひらがな・カタカナどちらでもよい。

| 記号 | 意味 | 例 |
| --- | --- | --- |
| `'` | 直前のモーラがアクセント核。無ければ平板 (0 型) | `ハ'シ` (橋) / `ハシ'` (端・尾高) / `ハシ` (平板) |
| `/` | アクセント句の境界 (ポーズなし) | `コンニチワ'/セカ'イ` |
| `、` | 短いポーズ (既定 0.2 秒、`pauseLength` で変更) | `ハ'イ、ワカリマ'_シタ` |
| `。` `？` `！` | 文末。`？` は文末上昇、`！` は文全体を強める | `デ_スカ？` |
| `_` | 直後のモーラを無声化 | `_シテ`、`デ_ス` |
| `ー` | 長音 (直前の母音を伸ばす) | `トーキョー` |

`_` が 1 つも無い場合、無声化規則 (無声子音に挟まれた イ・ウ、文末の ス) が自動で適用される。`トーキョーデス` と `トーキョーデ_ス` はどちらも `トーキョーデ_ス。` になる。

末尾の `、` は末尾ポーズとして残る。`。` などの文末記号は末尾に無音を足さない — 末尾の無音は `postPause` が決める。

かなとして解釈できない文字が混ざると `INVALID_INPUT` (`path: "$.kana[0]"`) で止まる:

```
Unrecognized reading "wo" in phrase "ハローworld".
hint: Write readings in kana; separate accent phrases with / and mark the accent nucleus with '.
```

## ローカル辞書

```json
{
  "entries": [
    { "id": "kongyoroid", "surface": "kongyoroid", "reading": "コンギョロイド", "accent": 0, "note": "product name" },
    { "surface": "端", "reading": "ハシ", "accent": 0, "match": "anywhere", "priority": 3 }
  ]
}
```

| フィールド | 内容 |
| --- | --- |
| `surface` | 一致させる表記 |
| `reading` | カタカナの読み |
| `accent` | アクセント核のモーラ位置。`0` = 平板。省略するとフロントエンドに任せる |
| `match` | `word` (既定) / `anywhere`。漢字 1 字など語境界を跨ぐものは `anywhere` |
| `priority` | 0–10 (既定 5)。競合時の優先度 |
| `id` | `dict update` / `dict delete` で指すための識別子 |

同じ読みが文中に複数ある場合は位置で照合するので、「橋の端」に `端 → ハシ (0)` を登録しても橋のアクセントは変わらない。同じ表記・同じ読みの `dict add` は `unchanged: true` の no-op。

適用されたかは `dictionaryHits[].applied` で確認する。`applied: false` は登録したのに効いていないということなので、`match` と `surface` の綴りを疑う。

## 韻律パラメータ

| フィールド (CLI フラグ) | 既定 | 範囲 | 内容 |
| --- | --- | --- | --- |
| `voice` (`--voice`) | `neutral` | 7 種 | 内蔵ボイス |
| `speed` (`--speed`) | 1 | 0.25–4 | 話速倍率。子音・母音・ポーズを一様に伸縮 |
| `pitchSemitones` (`--pitch-semitones`) | 0 | −24..24 | 基本ピッチの半音シフト |
| `intonation` (`--intonation`) | 1 | 0–3 | 抑揚の幅 |
| `volume` / `gainDb` | 1 / — | 0–3 / −60..12 | 出力レベル。**排他** |
| `breathiness` (`--breathiness`) | 0 | −1..1.5 | 声門の張り。正で息っぽく |
| `prePause` / `postPause` | 0.1 / 0.1 | 秒 | 前後の無音 |
| `pauseLength` / `pauseScale` | — / 1 | 秒 / 倍率 | `、` の絶対長 / 全ポーズの倍率 |
| `upspeak` (`--no-upspeak`) | true | — | 疑問文末の上昇 |
| `sampleRate` (`--sample-rate`) | 24000 | 8000–48000 | 出力レート |
| `seed` (`--seed`) | 1 | — | ノイズ・揺らぎの種 |
| `strictReading` (`--no-strict-reading`) | true | — | 読めない文字でエラーにするか |

効き方 (`validate` の `estimate.durationSeconds` と `plan` の `f0`):

| 変更 | 結果 |
| --- | --- |
| `speed` 0.8 / 1 / 1.5 | 1.89 秒 / 1.552 秒 / 1.101 秒 |
| `prePause: 0, postPause: 0` | 1.497 秒 → 1.297 秒 (合計 0.2 秒ぶん) |
| `pauseLength: 0.5` | 1.497 秒 → 1.797 秒 (`、` が 0.2 → 0.5 秒) |
| `pauseScale: 2` | 1.497 秒 → 1.697 秒 |
| `intonation` 0 / 1 / 3 | F0 幅 139–161 Hz / 148–249 Hz / 165–795 Hz |
| `upspeak: false` (`そうですか？`) | F0 上端 316.7 Hz → 252.4 Hz |

イントネーションは藤崎モデル (フレーズ指令 + アクセント指令) で生成され、文末の下降、疑問の上昇、感嘆の強調、段落末の長いポーズが付く。`intonation: 3` は F0 が大きく振れて不自然になりやすいので、強調したいときも 1.2–1.5 程度から試す。

`volume` と `gainDb` を両方書くと `INVALID_INPUT` (`Give either volume or gainDb, not both.`)。レベルはどちらか一方で指定する。

## 内蔵ボイス

| id | baseF0 | f0Range | 性格 |
| --- | --- | --- | --- |
| `neutral` | 170 Hz | 70–900 | 中性的な中音域。通知・検証の既定 |
| `female` | 225 Hz | 110–1100 | 短めの声道、やや息混じり |
| `male` | 115 Hz | 55–700 | 長めの声道、張りのある声門 |
| `child` | 290 Hz | 150–1300 | 小さな声道と高いピッチ |
| `soft` | 185 Hz | 80–900 | 息の多い穏やかな声、抑揚控えめ |
| `bright` | 215 Hz | 100–1100 | 張った明瞭な声、抑揚大きめ |
| `deep` | 92 Hz | 45–600 | とても低い声、落ち着いた調子 |

`kongyoroid voices --engine formant` が一次情報 (`hash` 付き)。歌唱でも同じボイスを使う。ボイスを変えると `voiceHash` が変わり、`planHash` と `sha256` も変わる。

用途の目安: 静かな通知は `soft`、騒がしい環境や注意喚起は `bright`、長いナレーションは `neutral` か `female`、権威づけたい読み上げは `deep`。

## 文とポーズ

- 文の切れ目は `。！？` と**改行**。改行 1 つでも別の文になる。`一行目` と `二行目` を改行で並べると `イッコー'メ。ニギョー'メ。` の 2 文になる。
- 空行 (段落の切れ目) はさらに長いポーズになる (同じ 2 文で改行のみ 2.784 秒、空行あり 3.104 秒)。
- 原稿の改行が意図しない文分割になっていないかは `reading` の `sentences[]` で確認できる。1 文にまとめたいなら改行を消すか、`、` に置き換える。

## レビューの手順

1. `kongyoroid reading --text "…"` で `kana` を出し、原稿と 1 対 1 で突き合わせる。数詞・助数詞・固有名詞・英単語・記号を優先。
2. `warnings[]` を読む。`ASCII_WORD_UNKNOWN` と `URL_READ_LITERALLY` は助言 (`severity: "advice"`) だが、たいてい直す価値がある。**警告が無いことは正しさの証明ではない**。
3. 直したい語を辞書か `kana` で上書きし、`dictionaryHits[].applied` で効いたことを確かめる。
4. `phrases[].accent` と `boundary` を見て、句切れと核が意図どおりか確認する。長い修飾句が 1 つの句に潰れているなら `kana` に `/` を入れて分ける。
5. `validate` で `estimate.durationSeconds` が尺の要件に合うか見る。合わなければ `speed` かポーズで調整し、原稿自体を削るかはユーザーに確認する。
6. 描画して `inspect`。`finite: true` / `clipped: 0` / 意図した尺を確認する。
